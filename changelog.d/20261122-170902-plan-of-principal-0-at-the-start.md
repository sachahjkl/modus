**The plan of principal 0 at the start.** The root service starts `plans` before the start policy and waits, within the hang bound, until it gives the roles of the current plan of principal 0, so the role holders that principal 0 applied hold from the first start of the machine. A machine with no data disk and a rescue start with no wait; a stored plan that a newer boot image cannot hold, or a damaged store, keeps the role holders of the image with one line, and the next `plans.apply` is no longer refused.
