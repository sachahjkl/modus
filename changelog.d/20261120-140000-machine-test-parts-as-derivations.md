**Machine test parts as derivations.** The check of the flake runs each test part in a derivation of its own, on the test inputs of a whole build named by the hash of their bytes, so a change of a document or of a host test runs no machine again and Nix takes each part from the store. `modustool screenshots` prints how many parts Nix took from the store and how many ran, and runs at most one part for each four processors. `modustool part_cache` proves the cache: after a change of an intent file or of a host test, each test part has the same derivation. A change of the sources of the tool or of the system still runs every part. Each part names the files of the build that it reads, and the whole build refuses, before any machine starts, a part that reads a file that its inputs lack. The test of the debug objects against the linked files moved from the part `host_modules` to `modustool check`.
