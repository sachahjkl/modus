**A machine with no screen.** A machine with no screen at its start no longer ends its start on a failure that nobody sees: the root service writes `root: no screen: no console; remote calls still reach the system`, starts no input service, no compositor and no console, gives no process a window, refuses a process that needs a terminal, and starts `remote` itself, so a client key that a principal allowed in an earlier run still calls the services. An `unlock` that needs a typed key writes one line and stops. A compositor that stops later gives one line, refuses the later windows and terminals, and starts nothing.
