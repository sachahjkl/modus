**The counted kernel.** `modustool fuzz operations` now runs on the test kernel `kernel_edge_counters`, which counts the edges of the kernel code that each operation sequence reaches, for the runner and its children only, on one processor, in counters that only the tool reads through the memory file of the machine; the tool keeps each sequence whose two runs agree on a new edge class, mutates the kept ones, writes the smallest set of them as the reach inputs of the corpus at the end of the run, and checks in each run that the counters stay at 0 outside the sequences and past the guards of the linked kernel. The release refuses that kernel by the hash that its description must name, by the test signing key of its volume, and by the text `kernel: TEST BUILD:` in the bytes of a kernel module, which refuses each test kernel; each build checks that the kernel that ships lacks that text and that each test kernel holds it, and a machine test of another volume fails when its log has the boot line of the counted kernel. The hashes of `kernel` and `kernel_without_return_check` change only through the line numbers in the messages of their bounds checks.
