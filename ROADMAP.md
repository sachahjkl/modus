# Roadmap

This file holds the planned work of modus. **Now** is the work that is in progress. **Next** is the work that is decided and comes after. **Later** is the work that is wanted and has no order. **Maybe** is what may be done one day and is not decided: each entry says the ways open and what each waits for. An entry leaves this file in the commit that ends its work.

## Now

## Next

- **The text grid measured against text runs.** The terminal draws a full grid both ways through the drawing module, and the kind `Text_Grid` stays only if the runs cost more than 1 ms more for a frame or more than 4 096 records. The format then has one text form, or a measured reason for two. [Design](src/md/api/draw_table.md)
- **The counted kernel.** A test kernel counts the edges of the kernel code that each operation sequence reaches, which only the tool reads, and the engine keeps the sequences that reach new code, which become the reach inputs of the corpus. The release refuses it by its hash, its signature and its bytes. [Design](src/md/infrastructure/kernel_fuzzing.md)
- **Every glyph drawn by its process.** The boot image no longer carries glyphs drawn at three sizes: each process draws every glyph of its text, measures every character from its font file, and a caller of the library module `text_rendering` gives the font outlines as bytes. A developer then draws a text at the size that a layout asks for. [Design](src/md/features/text_rendering.md)
- **A text size in the draw record.** A text record and a text grid carry a size in 1/64 pixel in place of one of three scales, and the elements take their sizes from the text size tokens, with a caption size of 14 and a heading size of 24. A card then has a caption smaller than its body, and a page of `manual` has headings. [Design](src/md/features/text_rendering.md)
- **The scale factor of the reference screen.** The windows, the spacing, the text and the pointers of the screen of 1920 × 1080 draw at a scale from 1.25 to 2, in place of scale 1, so a text on that screen has the size that a reader needs. The boot display is apart: it already takes its scale among the sizes of Spleen. [Design](src/md/features/desktop_to_browser.md)
- **The remote display.** A principal sees and drives the desktop of a machine from a native viewer, a program of its own that uses gui_toolkit, over QUIC with a client key that it allowed for the view or for the view and the input, with a mark in the bar while the viewer is connected. [Design](src/md/features/remote_display.md)

## Later

- **One drawer at a time in the private glyph cache.** A second thread of a process that draws text while the first draws is refused with one line, in place of a cache whose lists break under two writers. A developer then learns of the fault at its first frame, not from a wrong pixel later. [Design](src/md/features/text_rendering.md)
- **A firmware that hangs in the end of its services.** On a machine with Secure Boot and a TPM, OVMF once hung in `ExitBootServices` after `boot program: ok`, with no line for ever. The boot program arms the watchdog of the firmware with a short bound before that call, so that a hang of the firmware starts the machine again in place of freezing it. [Design](src/md/features/missing_hardware.md)

- **A silent data disk that freezes no processor.** On a disk with the default ioevent file of QEMU, the root service turns the bus master off over a request that never ends, QEMU then waits for that request, and every processor of the machine stops; only the test machine of the silent disk has no ioevent file. The machine of `run` and each test machine then get a form that QEMU does not drain, chosen after a measure of its cost for each request, so a silent disk gives its lines on every machine. [Design](src/md/features/missing_hardware.md)
- **A screen of memory.** A machine with no screen still has a desktop, at a size that its start list or a viewer gives, and a viewer sees it. [Design](src/md/features/remote_display.md)
- **An interface of the remote display for agents.** An agent takes a picture of the screen, and waits for the screen to settle or to change, from the damage of the compositor. [Design](src/md/features/remote_display.md)
- **The remote display in a browser.** A gateway gives the remote display to a browser by WebTransport, with a display token of one day that the viewer renews up to an absolute end that the principal gives, and that the principal can revoke, so a principal needs no viewer to install. [Design](src/md/features/remote_display.md)
- **The remote display in a browser by WebSocket.** A browser with no WebTransport reaches the same gateway by WebSocket, with the same token. [Design](src/md/features/remote_display.md)
- **The remote display through VNC and RDP.** A gateway gives the remote display to a client of VNC, then of RDP. [Design](src/md/features/remote_display.md)
- **A video codec for the remote display.** The pixel updates are coded in H.264 or AV1 when a measure of the bandwidth needs it, on the processor first, then through the GPU. [Design](src/md/features/remote_display.md)
- **A machine check or an NMI that stops one process.** The kernel reads the error of the machine check, and a corrected error or an error in the memory of one process gives a line or the stop of that process in place of a stop of the machine. [Design](src/md/features/missing_hardware.md)

- **The bus master off before a device service stops.** The root service turns the bus master of a device off, then stops its device service, for each device service, in place of stopping the service first. A device then makes no access to memory between the stop of its service and the reap, also on a machine with no IOMMU. [Design](src/md/features/device_services.md)
- **Sound of several processes at once.** A sound service of the class between the processes and the device service gives each process a timed stream of its own and sums their frames, so a second process plays in place of being refused. [Design](src/md/features/timed_stream.md)
- **The drift of the clock of a sound device.** The sound service measures the rate of its device from the times of the completions and changes its stream clock, so a record plays at its time after an hour on a real device. [Design](src/md/features/timed_stream.md)
- **Capture of sound.** A process with a grant reads the microphone as records of a timed stream, with a visible indicator while it reads. [Design](src/md/features/timed_stream.md)
- **A kernel copy out of a memory object.** A process copies bytes of a memory object that another process gave into its own memory with no mapping, and gets a refusal in place of a fault when the giver revokes the object. A paste then never stops the terminal, whatever the process that copied does. [Design](src/md/features/clipboard.md)
- **A selection, a cut and a paste in the palette.** The principal chooses a part of a text to copy, cuts it with Control+X, copies from the terminal and pastes into the palette, and each window with its own loop of events takes the clipboard keys. [Design](src/md/features/clipboard.md)
- **A terminal that the principal resizes.** The window of the terminal, and so the console, takes a size that the principal drags, and the process of the terminal gets the new count of columns and rows of its text grid. [Design](src/md/features/window_resize.md)
- **The ring of counter sets of the counted kernel.** The tool writes several operation sequences ahead, and each counted runner counts into its own set of counters, so the machine waits less for the tool. It comes only if the measure of the loop and of the counted kernel shows that these waits cost more than the sequences. [Design](src/md/infrastructure/kernel_fuzzing.md)
- **The other records at the addresses of the kernel operations.** The generator writes the event rules, the guest registers, the schedules, the placements and the address ranges by their types, as it writes the four records of today, so the fuzzing reaches the code behind the first check of each. An address range names a mapping whose address a sequence knows only at run time, so its table needs a writer in the runner. [Design](src/md/infrastructure/kernel_fuzzing.md)
- **The records of the states of Thread_Control.** A refusal of `Thread_Control` with `Bad_State` gives a record that names its state, such as a number that names no live thread, in place of the record `Refused`. A developer then reads why the control was refused. [Design](src/md/infrastructure/kernel_fuzzing.md)
- **Two processors in the kernel fuzzing.** Operation sequences with several threads run on two processors, so the fuzzing reaches the lock order and the wakes between processors. [Design](src/md/infrastructure/kernel_fuzzing.md)
- **A release with no test module.** The boot image of a release leaves out the module group `tests`, and the machine of Secure Boot boots that exact image, so a principal gets no module that is wrong on purpose and the release still ships the bytes that the tests ran. [Design](src/md/infrastructure/repository_layout.md)
- **A word in place of the enum fields that are left.** The kind of an event rule, the direction of a parameter of a module file, the stage, the error, the difference and the direction of a load error, the kinds and the states of the boot information that the boot program measured, the source of the date page and the kind of a remote request hold a word that each reader takes through its border. No shared record then holds a member that its writer did not name. [Design](src/md/infrastructure/choice_constants.md)
- **The main machine test in named sections.** The main machine holds about a quarter of the machine time and bounds the whole test that runs its parts at once; in sections that each state what they need, its sections run as parts at once, and a developer runs one section alone. [Design](src/md/infrastructure/machine_test_parts.md)
- **A step of a scenario as a tagged union of its kinds.** Each kind of step has only its own fields, so the compiler refuses a field that the kind does not read, and the run of each kind is one small procedure that a whole switch calls.
- **Byte layouts of the other formats.** The guides show the records of the kernel operations, the fault ring and the disk formats of the storage service byte by byte, as the guide of the module contract shows the module file. [Design](src/md/features/byte_layout.md)
- **A serial port that keeps every line of a flood.** A principal who debugs a flood of log lines sees every line on the serial port, and not a count of the lines that it lost. [Design](src/md/features/log_side_channels.md)
- **No defence against a cut int1 once the hosts run Linux 7.3.** The kernel stops reading the bytes of a process at a debug exception with no status, when every host of the test machines runs Linux 7.3 or later, whose KVM no longer gives a cut `int1` again. A debug exception then costs no read of the process, and the kernel keeps no rule for one bug of one hypervisor.
- **An outside module imports another outside module.** The import of a module of another project names a module of the same project, and not only a module of the system. A developer then writes a library module and the modules that import it outside the repository. [Design](src/md/infrastructure/third_party_module.md)
- **A guest that runs a whole system.** A guest gets several guest processors, an interrupt that its process injects, long mode, memory at the guest address 0, and memory that it writes and then executes. A process can then run a kernel of another system in it. [Design](src/md/features/guest.md)
- **Linux in a guest.** A principal runs Linux, and the processes of Linux, in a guest beside the processes of the system. [Design](src/md/features/foreign_systems.md)
- **Processes of NT.** A process of NT runs through Wine inside the Linux guest, with no work of its own in the system. [Design](src/md/features/foreign_systems.md)
- **Acceleration by the virtual GPU of the test machine.** A back end of the drawing module draws the draw table through the WebGPU subset of the system, over Vulkan to the host through Venus. The GPU then draws the windows and the pictures, and not the processor. [Design](src/md/features/gpu_access.md)
- **Vulkan to the host through Venus.** The commands of the system cross the virtual GPU of the test machine to the Vulkan of the host, the base of the WebGPU subset. [Design](src/md/features/gpu_access.md)
- **A machine test of a bridge from PCI Express to PCI.** The shared requester of such a bridge, on its secondary bus, the context table of that bus, and the interrupt entry that checks the shared requester run on a test machine with the IOMMU of Intel, and not only in the host tests. A developer then knows that the devices behind such a bridge work with the IOMMU on. [Design](src/md/infrastructure/iommu.md)
- **A device on a bus that the root service numbers after the start.** A device behind a bridge that the firmware left with no bus number gets its own domain with the IOMMU on. Today it gets none, and its accesses are refused. [Design](src/md/infrastructure/iommu.md)
- **The devices of a second root bus.** On a server with several root complexes, a device on a root bus other than 0 gets its own domain, and its reserved memory range stays mapped. Today such a device gets no domain, and its accesses are refused. [Design](src/md/infrastructure/iommu.md)
- **The test of a forged interrupt on the IOMMU of AMD.** A machine test shows that a unit of AMD refuses a message interrupt that its device was not given, and that the log names the device. The emulated unit of AMD records no event for a message that it refuses, so today this refusal is tested on the IOMMU of Intel only. [Design](src/md/infrastructure/iommu.md)
- **A reserved memory range of several devices on the IOMMU of AMD.** A machine whose firmware keeps memory for every device, or for a range of devices, runs with the IOMMU of AMD on. Today such a machine leaves the IOMMU off. [Design](src/md/infrastructure/iommu.md)
- **A receive queue for each endpoint.** On a device that has several queues, the frames of an endpoint arrive in the memory of its process. The network service then leaves the path of the data that a process receives. [Design](src/md/infrastructure/network_data_path.md)
- **The stores of a principal are encrypted.** The storage service encrypts the stores of a principal with the key of that principal. A reader of the disk who has no key reads no object.
- **Several principals, and one identity on several machines.** More than one named principal uses a machine, each with its own session and its own stores. A principal has the same identity on another machine, and a grant can be signed for a principal of another machine.
- **A profiler reads the processor counters of another thread.** A process that holds a thread of another process reads the counts of the processor for that thread. A profiler then measures a process that it did not write. [Design](src/md/features/processor_counters.md)
- **A pager for another process.** A process answers the page faults of another process and supplies its pages.
- **Every window uses the interface package.** The windows of the processes that still draw by themselves are built from the elements of the interface package. Each window then has the same look, the same keys and the same damage rules.
- **The history of a store.** A version is a state of a whole store, and the versions of each object are found in it. A principal then steps a store back as one thing, not object by object.
- **A faster switch between threads.** A processor that takes again the thread whose extended state its registers hold skips the restore of that state. A measure gives the gain.
- **A check of the share policy that the load of the host does not set.** The process `scheduler` checks that the weights order the shares of the processors by the ticks that each process got. The kernel no longer charges stolen time, but a processor that the host runs less still gets fewer ticks, so on a host whose cores are busy the order can fail; the check then counts the ticks of each processor that ran, and its result depends on the kernel only. [Design](src/md/features/stolen_time.md)
- **LLVM 22.** The build uses LLVM 22, with a measure of the speed of the code before and after. LLVM 22 has the fix of the order of dead store elimination, so the flake then builds no LLVM of its own. [Design](src/md/infrastructure/llvm_of_the_build.md)
- **An encrypted session with the TPM.** The machine key crosses the bus of a hardware TPM encrypted, in a salted session whose answers the TPM service checks, so a reader of the bus gets nothing. To build before a machine with a hardware TPM. [Design](src/md/features/tpm_sealed_machine_key.md)
- **The form of the record of the machine key pinned in the TPM.** The TPM keeps, under the policy of this system, which form the record of the machine key has, so another system on the machine that replaces or removes the record is refused and not only made visible. [Design](src/md/features/tpm_sealed_machine_key.md)
- **A recovery key for a named principal on a machine with no TPM.** A principal created on a machine with no TPM, or with Secure Boot off, gets a recovery key too, so a lost passphrase is not a lost principal there either. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **The state of the lockout hierarchy in the window of the creation.** When another system set the lockout value of the TPM, or the TPM refused a new one, the window of `unlock` says it once at the creation of a named principal, so the principal knows that the count of the wrong passphrases does not hold against that system. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **A new file under the passphrase alone is opened again before its write.** A change of the passphrase of the form `PRINCIPL` opens the new file with the new passphrase before it replaces the old one. A fault of the seal then cannot lose a principal that has no recovery key. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **The number of the principal in the start of a change.** The root service gives `unlock` the number of the principal that asked for a change, and `unlock` refuses a file of another principal. A change then stays right with several named principals. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **A disk grant table that a restore cannot roll back.** A counter of the TPM that only grows names the newest disk grant table of each principal, so a writer of the disk who kept an older table cannot bring back a grant of a disk process or a client key of `remote` that the principal revoked, such as the key of a stolen device. [Design](src/md/features/processes_from_a_disk.md)
- **The file of a named principal pinned in the TPM.** The TPM keeps which file of a named principal is current, so a writer of the disk who kept an older file cannot bring back an older passphrase. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **An update of the system that keeps the seal of the machine key.** The machine key is sealed to a policy that the publisher of the system signs, with the version floor of the TPM, so a new system opens it with no recovery key and an older system still opens nothing. [Design](src/md/features/tpm_sealed_machine_key.md)
- **A remote attestation of the measure.** A remote machine asks the TPM for a signed quote of PCR 7, PCR 11 and PCR 12 with a nonce of its own, and checks it against the system descriptions that it expects. A principal then knows which system runs on a machine that it does not see. [Design](src/md/features/rollback_floors.md)
- **The TPM floors kept against code with the TPM.** The storage hierarchy of the TPM gets an authorization value that the system keeps sealed by the TPM, so another system on the machine can no longer remove a floor and start an older signed system that then keeps its own numbers as the floors. It leaves open a compromise of the code that holds that value, the kernel or the TPM service, and a change of PCR 7. [Design](src/md/features/rollback_floors.md)
- **The TPM floors kept across a change of PCR 7.** The policy of a floor names a key of the publisher (`TPM2_PolicyAuthorize`) in place of the value of PCR 7, so an update of `dbx` or of the firmware no longer lets one older signed system start and make its numbers the floors. [Design](src/md/features/rollback_floors.md)
- **The network libraries become modules.** TCP, QUIC and the cryptography are loaded one time and imported, as the drawing module is. One correction then reaches every process that uses the network. [Design](src/md/api/library_modules.md)
- **Fresh bytes for the services and the children of a process.** The device services, the TPM service, `input`, a terminal and a process that another process starts get a fresh bytes page too. A key that the TPM service or a child of the console makes late in its life then has bytes newer than its start. [Design](src/md/features/fresh_bytes.md)
- **A budget for each source of a QUIC flood.** A flood of new connections from one range of addresses spends only the budget of that range. Clients from other addresses then still connect while it lasts.
- **A font for the missing Greek letters, Cyrillic and Latin Extended-A.** A font of the system with Π, ρ, the Cyrillic letters and Latin Extended-A joins the fallback chains, and the compositor stops naming them as missing on the log. A principal then writes Greek, Russian and the languages of Central Europe in every window and in the cells. [Design](src/md/features/glyphs_on_demand.md)
- **A font for the CJK ideographs.** A TrueType font with the ideographs joins the fallback chains, with a cell of two columns in the terminal. A principal then reads and writes Chinese, Japanese and Korean. [Design](src/md/features/glyphs_on_demand.md)
- **The shaping of complex scripts in the process.** A script whose glyphs join or change their order (Arabic, the scripts of India) is shaped in the process that draws it, from the font outlines. A principal then reads these scripts as they are written. [Design](src/md/features/glyphs_on_demand.md)
- **A processor time that the other processes do not set.** The processor time of a process is an amount that its budget holds and divides among its children, as its log records are. A thread then cannot learn from its own share that a sibling ran. [Design](src/md/features/log_side_channels.md)
- **A document service with a picker.** A service owns the objects of the principal that belong to no one process, and gives a process a handle to a document only when the principal picks it. The principal then lists and revokes each grant of a document (`docs/ARCHITECTURE.md`, section U6).
- **The host tests of the check in the measure record.** The measure record counts the host tests of `modustool check` beside the machine tests and the second build of `modustool screenshots`. The site then shows the count of every check of a release.
- **The boot program named in the processors of a failed step.** The tool learns where the firmware loaded the boot program, so an instruction address of a processor there names the boot program and not "no known code". A stall between the start of the boot program and the kernel then says which of the two held the processor.
- **Layout from the size of the content.** A label is as wide as its text and a column as wide as its widest child, so a window keeps its order at any size. [Design](src/md/features/desktop_to_browser.md)
- **A resolution and a scale that the principal chooses.** The principal sets the mode of the display and a scale of the interface, and every window draws at that scale. [Design](src/md/features/desktop_to_browser.md)
- **Floating windows that snap to the edges.** The principal moves, maximizes, minimizes and snaps the windows to the edges and the halves of the screen, and a global shortcut always reaches the system. [Design](src/md/features/desktop_to_browser.md)
- **Workspaces.** The principal keeps groups of windows on several workspaces and moves between them with a key. [Design](src/md/features/desktop_to_browser.md)
- **A blur in the draw table, with the GPU.** A process draws a frosted surface or a soft shadow, at the cost of the GPU and not of the processor. [Design](src/md/api/draw_table.md)
- **Drag and drop between windows.** The principal drags a document onto a window, and that process receives it at the drop only. [Design](src/md/features/desktop_to_browser.md)
- **PNG and JPEG pictures in a process.** A process shows a picture of these formats, and a hostile file stops only the decoder that read it. [Design](src/md/features/desktop_to_browser.md)
- **Vector forms in the picture decoders.** The filters of PNG and the transform and the colors of JPEG run in SSE2 forms that give the bytes of the scalar forms, so a large picture opens sooner. [Design](src/md/features/desktop_to_browser.md)
- **Vector forms of the paths, the blends and the horizontal gradient.** The coverage of a path, the blend of a translucent record and the horizontal gradient run in SSE2 forms, so a frame of the compositor costs less. [Design](src/md/features/desktop_to_browser.md)
- **Notifications.** A process shows a short text to the principal, in a place that no process can imitate, and the focus stays where it was. [Design](src/md/features/desktop_to_browser.md)
- **Buffers that pass through several processes with no copy.** A picture goes from the network to a decoder to the screen with no copy, and each process reads it with no right to change it. [Design](src/md/features/desktop_to_browser.md)
- **Large pages for surfaces, decoded pictures and arenas.** A process that holds large buffers misses the translation cache of the processor less, where a measure shows a gain. [Design](src/md/features/desktop_to_browser.md)
- **TLS 1.3 over TCP.** A process opens an encrypted TCP connection with the same TLS code as QUIC. [Design](src/md/features/desktop_to_browser.md)
- **HTTP/1.1 and HTTP/3 for a process.** A process fetches a resource of the web from a server of either version. [Design](src/md/features/desktop_to_browser.md)
- **Cookies and a cache for each principal.** A browser keeps the cookies and the cache of each principal apart, so two principals share neither. [Design](src/md/features/desktop_to_browser.md)
- **An HTML parser that fuzz targets try to break.** A process reads the HTML of any page into a tree as the WHATWG defines it, and a hostile page stops only the parser. [Design](src/md/features/desktop_to_browser.md)
- **Web pages with a subset of CSS.** A page shows its block, inline and flex layout, with its text shaped by the system. [Design](src/md/features/desktop_to_browser.md)
- **A light web browser, one process for each origin.** A principal reads pages of documents, follows links, goes back and sends forms, and a page of one origin reads nothing of another. [Design](src/md/features/desktop_to_browser.md)
- **3D on the processor, through the WebGPU subset.** A process draws 3D with no GPU through the same buffers, pipelines and draw calls as on a GPU, with a fixed set of shaders in Odin with SIMD, so only the back end changes when a GPU comes. [Design](src/md/features/desktop_to_browser.md)
- **The screen through the virtual GPU.** The compositor shows its screen through the 2D scanout of the virtual GPU of the test machine, the first step to the GPU. [Design](src/md/features/gpu_access.md)
- **A USB keyboard and a USB pointer.** A principal types and points with USB devices, which reach only the window that has the focus. [Design](src/md/features/device_services.md)
- **NVMe disks.** The storage service keeps its stores on an NVMe disk as on a virtio disk. [Design](src/md/features/device_services.md)
- **Device services for the devices of a real machine.** The root service starts the device service of each device by its identity, and a principal grants a device service from the disk for one device. [Design](src/md/features/device_services.md)
- **A device service that fails starts again.** The class service keeps its ring, so the processes above it see a delay and not a stop. [Design](src/md/features/device_services.md)
- **Devices that only Linux serves, through a driver domain.** A principal uses a Wi-Fi card or another device with only a Linux driver, through a guest that serves its class protocol. [Design](src/md/features/device_services.md)
- **Odin modules of other projects on the system.** A module written for the core library of Odin runs on the system, with its files in its private store. [Design](src/md/features/desktop_to_browser.md)
- **gui_toolkit, the toolkit of rich modules.** Each application of the toolkit runs in a window of the system as an outside module, and a developer writes a rich module with it. [Design](src/md/features/desktop_to_browser.md)
- **The look of the system as a style of gui_toolkit.** A rich module can show the grid of points, the cards, the folded gap and the colors of the concepts of the system. [Design](src/md/features/desktop_to_browser.md)

## Maybe

- **An environment and arguments built for a ported module.** A ported module reads `HOME`, `LANG` or `argv` from a layer that builds them from its start record, in place of a change of its code. Two ways are open: each port adapts its code to the handles, the settings and the values of the context, which is the rule today; or one layer for ported modules only, which waits for the first ports and what they read. [Design](src/md/features/desktop_to_browser.md)
- **An auto_cast to a type that is no enum, past the check of the casts.** The check of the casts refuses each `auto_cast`, because the syntax tree does not hold its target, and it would accept one whose target is no enum. Two ways are open: the types that the compiler infers, which wait for an output of `odin check` that names the type of each expression, or a type checker in the tool, which waits for a need of the system that a written conversion does not meet. [Design](src/md/infrastructure/choice_constants.md)
- **A machine case for the refused ring words of the frame and palette rings.** The frame service and the palette provider of the console show on a machine that they answer the refused words as their host-tested borders decided. Their one writer is the network service or the compositor, so two ways are open: a test module that holds their ring, which waits for a choice to give a test module the grant `Network_Device` or the place of the compositor; or a test build of the writer that sends the words, which waits for a choice to put test code in a module of the system. [Design](src/md/infrastructure/choice_constants.md)

- **A guest on a machine with an Intel processor.** A process runs a guest on a machine with an Intel processor too, with the same operation and the same exit records as on AMD. One way is open, and it waits for a host with an Intel processor: QEMU emulates no VMX, so only such a host runs the machine test of it. [Design](src/md/features/guest.md)
- **The release image started on a real machine.** The image starts from a USB key on the UEFI firmware of a real machine, with the certificate of the publisher enrolled, Secure Boot on and the machine key sealed by its TPM. One way is open, and it waits for a real machine with a TPM and a USB key: today the image starts in the machine test only, on the firmware of QEMU. [Design](src/md/infrastructure/release_image.md)
- **A whole frame on the display of a real machine.** The compositor flips its screen pages on a real display too, writes the page that the display showed only after its next vertical blank, and writes the pixels through a write-combining entry of the page attribute table, which the kernel sets at the start, and not through the memory type that the firmware chose. One way is open, and it waits for a real machine whose display offers a page flip: today the flip uses the display registers of the standard VGA of QEMU, whose flip takes effect when its write returns. [Design](src/md/infrastructure/whole_frame.md)
- **Acceleration by a real GPU.** The draw table is drawn through WebGPU on a real GPU through a driver domain, so the GPU draws the windows and the pictures of a real machine. One way is open, and it waits for a real machine with a GPU and an IOMMU: QEMU gives a virtual GPU only. [Design](src/md/features/gpu_access.md)
- **A remapping unit that the firmware left with its queue of invalidations on.** The kernel takes over the queue of such a unit, so the unit runs with the IOMMU on, where today it leaves the IOMMU off. Two ways are open, a real machine whose firmware leaves the queue on or a firmware for the test machine that turns it on, and each waits for that machine or that firmware: QEMU has no option for it. [Design](src/md/infrastructure/iommu.md)
- **A thread stopped at the limit of its budget, not at the next tick.** A thread that reaches the limit of its budget stops at that moment, not up to one tick later. One way is open, a timer of each processor in the TSC deadline mode set to the earlier of the next tick and the time left in the budgets of the thread, and it waits for a need: the next period already takes back what a budget used past its part. [Design](src/md/features/stolen_time.md)
- **Measures on a quiet host.** The numbers of the windows, of the calls, of the vector forms and of QUIC are measured on a host with no other load, so a reader compares them from one release to the next. One way is open, and it waits for a host with no other load.
- **The option for the debug information in the compiler of the Odin project.** The kind of debug information that adds no instruction is offered to the Odin project, so a developer builds the modules of the system with the compiler of that project, with no fork. One way is open, and it waits for an issue opened upstream, then for the answer of the Odin project. [Design](src/md/infrastructure/debug_information_and_code.md)
- **The cache of the site workflow.** The workflow keeps the store paths of the development shell in the cache of GitHub Actions or in FlakeHub Cache. The cache of GitHub Actions is in use; FlakeHub Cache waits for a FlakeHub account for the repository.
- **An embedded font for the text of the site.** The site carries the ASCII subsets of Paper Mono, whose license (the SIL OFL 1.1 with no Reserved Font Name) allows the copy, in place of the fonts of the system of the reader. One way is open, and it waits for a choice between one more download for each reader and one look on every system.
- **The first engine of WebAssembly: a compiler or an interpreter.** Two ways are open: a compiler at run time, whose code stays in its process under the rule of property 11 and which waits for a design of a switch of a page from Write to Execute, or an interpreter, which waits for a measure that says it is fast enough for the rich modules of gui_toolkit. [Design](src/md/features/desktop_to_browser.md)
- **Tiling of the windows, as an option.** The principal lets the compositor place the windows side by side with no overlap. One way is open, a mode of the window manager beside the floating windows, and it waits for the workspaces and for a principal who asks for it. [Design](src/md/features/desktop_to_browser.md)
- **A port of wgpu or Dawn for a module of a third party.** A module of a third party brings its own implementation of WebGPU as its module, over the WebGPU subset of the system. One way is open, and it waits for the WebGPU subset and for a module that needs more than it gives. [Design](src/md/features/gpu_access.md)
- **JavaScript in the light browser.** Two ways are open: an engine written for the system, which waits for the light browser and a measure of its size, or the engine in Odin of gui_toolkit, which waits for the target of the core library of Odin. [Design](src/md/features/desktop_to_browser.md)
- **The browser wren on the system with no guest.** Two ways are open for its Rust libraries, a Rust target for the system or Odin code in their place, and each waits for that work; both wait for code that a process writes then runs, and for WebGPU on a GPU. [Design](src/md/features/desktop_to_browser.md)
