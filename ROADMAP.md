# Roadmap

This file holds the planned work of modus. **Now** is the work that is in progress. **Next** is the work that is decided and comes after. **Later** is the work that is wanted and has no order. An entry leaves this file in the commit that ends its work.

## Now

## Next

- **The keys of a named principal sealed by the TPM, and their recovery key.** The TPM releases the keys of a named principal only to the system whose measure it holds, and counts the wrong passphrases, so a copy of the disk allows no tries without limit. A principal who loses the passphrase opens the stores again with a recovery key. [Design](src/md/features/tpm_sealed_machine_key.md)
- **A guest on a machine with an Intel processor.** A program runs a guest on a machine with an Intel processor too, with the same operation and the same exit records as on AMD. [Design](src/md/features/guest.md)

## Later

- **The screen shows each frame of the compositor whole.** The compositor puts a frame on the screen in one step, by a page flip or at the vertical blank, so a window that changes many times a second never shows a cut between two of its pictures. [Design](src/md/infrastructure/whole_frame.md)
- **An outside module imports another outside module.** The import of a module of another project names a module of the same project, and not only a module of the system. A developer then writes a library module and the programs that import it outside the repository. [Design](src/md/infrastructure/third_party_module.md)
- **The option for the debug information in the compiler of the Odin project.** The kind of debug information that adds no instruction is offered to the Odin project. A developer then builds the modules of the system with the compiler of that project, with no fork. [Design](src/md/infrastructure/debug_information_and_code.md)
- **A guest that runs a whole system.** A guest gets several guest processors, an interrupt that its program injects, long mode, memory at the guest address 0, and memory that it writes and then executes. A program can then run a kernel of another system in it. [Design](src/md/features/guest.md)
- **Linux in a guest.** A principal runs Linux, and the programs of Linux, in a guest beside the programs of the system. [Design](src/md/features/foreign_systems.md)
- **Programs of NT.** A program of NT runs through Wine inside the Linux guest, with no work of its own in the system. [Design](src/md/features/foreign_systems.md)
- **Acceleration by a GPU.** The one graphics interface of the system runs in software first, then on the virtual GPU of the test machine, then on a real GPU through a driver domain. The GPU then draws the windows and the pictures, and not the processor. [Design](src/md/features/gpu_access.md)
- **One shared domain for the devices behind a conventional bridge.** The devices behind an older bridge of PCI, which share one requester, work with the IOMMU on when one service drives all of them. Today each of their accesses is refused. [Design](src/md/infrastructure/iommu.md)
- **A device on a bus that the root service numbers after the start.** A device behind a bridge that the firmware left with no bus number gets its own domain with the IOMMU on. Today it gets none, and its accesses are refused. [Design](src/md/infrastructure/iommu.md)
- **The devices of a second root bus.** On a server with several root complexes, a device on a root bus other than 0 gets its own domain, and its reserved memory range stays mapped. Today such a device gets no domain, and its accesses are refused. [Design](src/md/infrastructure/iommu.md)
- **The test of a forged interrupt on the IOMMU of AMD.** A machine test shows that a unit of AMD refuses a message interrupt that its device was not given, and that the log names the device. The emulated unit of AMD records no event for a message that it refuses, so today this refusal is tested on the IOMMU of Intel only. [Design](src/md/infrastructure/iommu.md)
- **A reserved memory range of several devices on the IOMMU of AMD.** A machine whose firmware keeps memory for every device, or for a range of devices, runs with the IOMMU of AMD on. Today such a machine leaves the IOMMU off. [Design](src/md/infrastructure/iommu.md)
- **A remapping unit that the firmware left with its queue of invalidations on.** The kernel takes over the queue of such a unit, so the unit runs with the IOMMU on, where today it leaves the IOMMU off. [Design](src/md/infrastructure/iommu.md)
- **A receive queue for each endpoint.** On a device that has several queues, the frames of an endpoint arrive in the memory of its program. The network service then leaves the path of the data that a program receives. [Design](src/md/infrastructure/network_data_path.md)
- **The stores of a principal are encrypted.** The storage service encrypts the stores of a principal with the key of that principal. A reader of the disk who has no key reads no object.
- **Several principals, and one identity on several machines.** More than one named principal uses a machine, each with its own session and its own stores. A principal has the same identity on another machine, and a grant can be signed for a principal of another machine.
- **A grant for the key of a client of `remote`.** The principal gives the public key of a client to the program `remote` as a grant that can be revoked. A call from another machine then acts only for a principal who allowed that client.
- **Processor counters for a program.** A program reads the counters of the processor for its own code, such as the cache misses. A developer then measures the cost of a data layout, and not only its time.
- **A pager for another program.** A program answers the page faults of another program and supplies its pages.
- **Every window uses the interface package.** The windows of the programs that still draw by themselves are built from the elements of the interface package. Each window then has the same look, the same keys and the same damage rules.
- **The wheel of a pointing device moves a view.** The wheel moves the view that is under the pointer: the lines of a terminal, a list, the palette. A principal then reads a long content with no press on a scroll bar. [Design](src/md/features/scroll_bar.md)
- **Keys that type characters outside ASCII.** A key gives a character of Unicode, so the layout of France gives é, è, ç, à and ù, and the fonts draw the Latin-1 Supplement in place of the replacement glyph. A principal then types the words of a language other than English in the console, its history and a passphrase. [Design](src/md/features/keyboard_layout.md)
- **The program `manual` opens the links of a page.** A link to a term, a guide or a declaration in the documentation of a module opens its page in the program `manual`. Today only a link to a module or to an export opens.
- **The console colors each field by its value kind.** The description of a field of a record states its value kind, so the console draws a size, a time or a handle in a field in its color. Today a field has the color of its type only.
- **The history of a store.** A version is a state of a whole store, and the versions of each object are found in it. A principal then steps a store back as one thing, not object by object.
- **The same object is kept one time.** The storage service finds an object by its hash, so an object that two entries name takes its blocks once.
- **A faster switch between threads.** A processor that takes again the thread whose extended state its registers hold skips the restore of that state. A measure gives the gain.
- **The history of each measure, release by release.** The measure record keeps the numbers of each release, and the site draws a chart of each measure over the releases. A reader then sees whether a change made the system faster or slower.
- **Measures on a quiet host.** The numbers of the windows, of the calls, of the vector forms and of QUIC are measured on a host with no other load. A reader then compares them from one release to the next.
- **LLVM 22.** The build uses LLVM 22, with a measure of the speed of the code before and after. LLVM 22 has the fix of the order of dead store elimination, so the flake then builds no LLVM of its own. [Design](src/md/infrastructure/llvm_of_the_build.md)
- **A dropped write found before the next commit.** The storage service reads back the blocks of the disk between commits, so a dropped write is found while the commit before it is still whole on the disk. A program then loses one commit, not the state of an object. [Design](src/md/features/dropped_write.md)
- **The machines of the TPM run in the full check.** The cause of the lost answer of the software TPM to the firmware is found, so the test of the measured boot runs at each full check and not only on request.
- **An encrypted session with the TPM.** The machine key crosses the bus of a hardware TPM encrypted, in a salted session whose answers the TPM service checks, so a reader of the bus gets nothing. To build before a machine with a hardware TPM. [Design](src/md/features/tpm_sealed_machine_key.md)
- **The form of the record of the machine key pinned in the TPM.** The TPM keeps, under the policy of this system, which form the record of the machine key has, so another system on the machine that replaces or removes the record is refused and not only made visible. [Design](src/md/features/tpm_sealed_machine_key.md)
- **The machine passphrase and the TPM together.** The machine passphrase becomes the authorization value of the machine key that the TPM seals, so the TPM counts each wrong try, and a changed system opens nothing even with the passphrase. [Design](src/md/features/tpm_sealed_machine_key.md)
- **An update of the system that keeps the seal of the machine key.** The machine key is sealed to a policy that the publisher of the system signs, with a counter of the TPM, so a new system opens it with no recovery key and an older system still opens nothing. [Design](src/md/features/tpm_sealed_machine_key.md)
- **A system description that cannot be rolled back.** A counter in the TPM refuses an older signed system description, and a list of revoked keys refuses a key of the publisher that leaked. A remote machine can then ask the TPM for an attestation of the measure.
- **Module records protected from their program.** The kernel marks each module record with its writer, and a program cannot change a record that its starter wrote. A report then says which modules a program really holds.
- **Error details for the kernel operations.** A kernel operation gives a table of error details, as an export does, once a measure shows the cost of one instruction for each command. A program then learns each wrong argument of a refused command, not only the first.
- **Every service gives an error record.** Each export of a service that fails gives an error record with its detail, not a negative number. A caller then reads why a call failed in every service.
- **The network libraries become modules.** TCP, QUIC and the cryptography are loaded one time and imported, as the drawing module is. One correction then reaches every program that uses the network. [Design](src/md/api/library_modules.md)
- **An entropy device.** The root service reads the random device of the machine to seed each program, and a program asks for fresh bytes while it runs. The seed of a program then does not depend on the processor alone.
- **A budget for each source of a QUIC flood.** A flood of new connections from one range of addresses spends only the budget of that range. Clients from other addresses then still connect while it lasts.
- **A grant for one channel of the log.** A reader of the log receives the records of the channels that it was granted, and no other. A program then shows its own records without the right to read the whole machine.
- **Glyphs drawn on demand.** A font service draws the glyphs that a text needs into a shared cache, in place of a cache filled whole at build time. A principal then uses more fonts and more characters with no larger boot image.
- **The reuse list of the properties is checked.** The list of the software that the system reuses names only what the system uses, each with its licence read at its source. A reader then trusts what the list says.
- **The share policy counts a thread that starts and ends between two rounds.** A program that creates threads which end before the next round of the share policy gets no more of the processors than a program with one thread. [Design](src/md/features/scheduling_policy.md)
