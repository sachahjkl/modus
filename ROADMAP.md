# Roadmap

This file holds the planned work of modus. **Now** is the work that is in progress. **Next** is the work that is decided and comes after. **Later** is the work that is wanted and has no order. An entry leaves this file in the commit that ends its work.

## Now

## Next

- **A terminal that always draws the end of an output.** On two runs of the main test, the terminal stayed on the state of a running call after the console had written the whole result: the row, the count of rows and the next line were in the log, not on the screen, with every program in a wait. The terminal now logs a lost wake of its reader or of its drawer, so the next run that shows it names the side that lost it, and a principal never sees a stale screen until the next key.
- **The first signed release image.** The keys of the publisher of the system go into the secrets of the repository, and their public key and certificate into `resources/keys`. The next tag then publishes a disk image that a principal verifies and starts. [Design](src/md/infrastructure/release_image.md)
- **A machine test of zeros that the disk does not keep.** The test disk drops a write of zeros of an erase of versions, and the machine test of `principals` checks the line of the storage service and the count of the row, so the report of the old bytes that stay on the disk is proved on a machine and not only read in the code. [Design](src/md/features/version_erase.md)
- **A guest on a machine with an Intel processor.** A program runs a guest on a machine with an Intel processor too, with the same operation and the same exit records as on AMD. [Design](src/md/features/guest.md)

## Later

- **The time zone as a setting.** The principal sets the time zone of the machine, the bar shows the local time, and the setting `appearance` `auto` turns light at 07:00 of the local time and not of UTC. The rule of the day already reads the zone of the date page. [Design](src/md/features/appearance.md)
- **The light values of the colors that programs own.** The measures, the states and the headings that twenty programs draw in colors of their own (`clock`, `log`, `manual`, `rings` and others) get a value in the light appearance that keeps 4.5 to 1 there. Today they keep their dark value on the light surfaces. [Design](src/md/features/appearance.md)
- **The release image started on a real machine.** The image starts from a USB key on the UEFI firmware of a real machine, with the certificate of the publisher enrolled and Secure Boot on, and the machine key sealed by its TPM. Today the image starts in the machine test only, on the firmware of QEMU. [Design](src/md/infrastructure/release_image.md)
- **The screen shows each frame of the compositor whole.** The compositor puts a frame on the screen in one step, by a page flip or at the vertical blank, so a window that changes many times a second never shows a cut between two of its pictures. [Design](src/md/infrastructure/whole_frame.md)
- **An outside module imports another outside module.** The import of a module of another project names a module of the same project, and not only a module of the system. A developer then writes a library module and the programs that import it outside the repository. [Design](src/md/infrastructure/third_party_module.md)
- **The option for the debug information in the compiler of the Odin project.** The kind of debug information that adds no instruction is offered to the Odin project. A developer then builds the modules of the system with the compiler of that project, with no fork. [Design](src/md/infrastructure/debug_information_and_code.md)
- **A guest that runs a whole system.** A guest gets several guest processors, an interrupt that its program injects, long mode, memory at the guest address 0, and memory that it writes and then executes. A program can then run a kernel of another system in it. [Design](src/md/features/guest.md)
- **Linux in a guest.** A principal runs Linux, and the programs of Linux, in a guest beside the programs of the system. [Design](src/md/features/foreign_systems.md)
- **Programs of NT.** A program of NT runs through Wine inside the Linux guest, with no work of its own in the system. [Design](src/md/features/foreign_systems.md)
- **Acceleration by a GPU.** The one graphics interface of the system runs in software first, then on the virtual GPU of the test machine, then on a real GPU through a driver domain. The GPU then draws the windows and the pictures, and not the processor. [Design](src/md/features/gpu_access.md)
- **One shared domain for the devices behind a conventional bridge.** The devices behind an older bridge of PCI, which share one requester, work with the IOMMU on when one service drives all of them. Today each of their accesses is refused. [Design](src/md/infrastructure/iommu.md)
- **A device on a bus that the root service numbers after the start.** A device behind a bridge that the firmware left with no bus number gets its own domain with the IOMMU on. Today it gets none, and its accesses are refused. [Design](src/md/infrastructure/iommu.md)
- **The devices of a second root bus.** On a server with several root complexes, a device on a root bus other than 0 gets its own domain, and its reserved memory range stays mapped. Today such a device gets no domain, and its accesses are refused. [Design](src/md/infrastructure/iommu.md)
- **The test of a forged interrupt on the IOMMU of AMD.** A machine test shows that a unit of AMD refuses a message interrupt that its device was not given, and that the log names the device. The emulated unit of AMD records no event for a message that it refuses, so today this refusal is tested on the IOMMU of Intel only. [Design](src/md/infrastructure/iommu.md)
- **A reserved memory range of several devices on the IOMMU of AMD.** A machine whose firmware keeps memory for every device, or for a range of devices, runs with the IOMMU of AMD on. Today such a machine leaves the IOMMU off. [Design](src/md/infrastructure/iommu.md)
- **A remapping unit that the firmware left with its queue of invalidations on.** The kernel takes over the queue of such a unit, so the unit runs with the IOMMU on, where today it leaves the IOMMU off. [Design](src/md/infrastructure/iommu.md)
- **A receive queue for each endpoint.** On a device that has several queues, the frames of an endpoint arrive in the memory of its program. The network service then leaves the path of the data that a program receives. [Design](src/md/infrastructure/network_data_path.md)
- **The stores of a principal are encrypted.** The storage service encrypts the stores of a principal with the key of that principal. A reader of the disk who has no key reads no object.
- **Several principals, and one identity on several machines.** More than one named principal uses a machine, each with its own session and its own stores. A principal has the same identity on another machine, and a grant can be signed for a principal of another machine.
- **The client keys of `remote` across a restart.** A client key that a principal allowed lasts across a restart of the machine, as a row of the disk grant table of its principal. Today the grant lasts until the machine stops. [Design](src/md/features/remote_client_keys.md)
- **A machine whose hypervisor refuses the counters that it lists still starts.** The kernel tries each counter register once at boot, and on a refusal of the processor it uses no counters and says so, where today such a machine stops at boot. The kernel also refuses the counters when the firmware left one of them on, as another user of them. [Design](src/md/features/processor_counters.md)
- **A profiler reads the processor counters of another thread.** A program that holds a thread of another program reads the counts of the processor for that thread. A profiler then measures a program that it did not write. [Design](src/md/features/processor_counters.md)
- **A pager for another program.** A program answers the page faults of another program and supplies its pages.
- **Every window uses the interface package.** The windows of the programs that still draw by themselves are built from the elements of the interface package. Each window then has the same look, the same keys and the same damage rules.
- **The history of a store.** A version is a state of a whole store, and the versions of each object are found in it. A principal then steps a store back as one thing, not object by object.
- **A faster switch between threads.** A processor that takes again the thread whose extended state its registers hold skips the restore of that state. A measure gives the gain.
- **Measures on a quiet host.** The numbers of the windows, of the calls, of the vector forms and of QUIC are measured on a host with no other load. A reader then compares them from one release to the next.
- **LLVM 22.** The build uses LLVM 22, with a measure of the speed of the code before and after. LLVM 22 has the fix of the order of dead store elimination, so the flake then builds no LLVM of its own. [Design](src/md/infrastructure/llvm_of_the_build.md)
- **An encrypted session with the TPM.** The machine key crosses the bus of a hardware TPM encrypted, in a salted session whose answers the TPM service checks, so a reader of the bus gets nothing. To build before a machine with a hardware TPM. [Design](src/md/features/tpm_sealed_machine_key.md)
- **The form of the record of the machine key pinned in the TPM.** The TPM keeps, under the policy of this system, which form the record of the machine key has, so another system on the machine that replaces or removes the record is refused and not only made visible. [Design](src/md/features/tpm_sealed_machine_key.md)
- **The machine passphrase and the TPM together.** The machine passphrase becomes the authorization value of the machine key that the TPM seals, as the passphrase of a named principal is, so the TPM counts each wrong try, and a changed system opens nothing even with the passphrase. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **A recovery key for a named principal on a machine with no TPM.** A principal created on a machine with no TPM, or with Secure Boot off, gets a recovery key too, so a lost passphrase is not a lost principal there either. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **The state of the lockout hierarchy in the window of the creation.** When another system set the lockout value of the TPM, or the TPM refused a new one, the window of `unlock` says it once at the creation of a named principal, so the principal knows that the count of the wrong passphrases does not hold against that system. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **No window of `unlock` outlives a lock.** A lock also ends the window that shows the recovery key of a creation or of a machine key, and the window that sets the machine passphrase, with a form that loses no recovery key that nobody wrote down. Anyone at the keyboard of a locked machine then sees no recovery key and sets no machine passphrase. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **A new file under the passphrase alone is opened again before its write.** A change of the passphrase of the form `PRINCIPL` opens the new file with the new passphrase before it replaces the old one. A fault of the seal then cannot lose a principal that has no recovery key. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **The number of the principal in the start of a change.** The root service gives `unlock` the number of the principal that asked for a change, and `unlock` refuses a file of another principal. A change then stays right with several named principals. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **The file of a named principal pinned in the TPM.** The TPM keeps which file of a named principal is current, so a writer of the disk who kept an older file cannot bring back an older passphrase. [Design](src/md/features/tpm_sealed_principal_keys.md)
- **An update of the system that keeps the seal of the machine key.** The machine key is sealed to a policy that the publisher of the system signs, with the version floor of the TPM, so a new system opens it with no recovery key and an older system still opens nothing. [Design](src/md/features/tpm_sealed_machine_key.md)
- **A remote attestation of the measure.** A remote machine asks the TPM for a signed quote of PCR 7 and PCR 11 with a nonce of its own, and checks it against the system descriptions that it expects. A principal then knows which system runs on a machine that it does not see. [Design](src/md/features/rollback_floors.md)
- **The TPM floors kept against code with the TPM.** The storage hierarchy of the TPM gets an authorization value that the system keeps sealed by the TPM, so another system on the machine can no longer remove a floor and start an older signed system that then keeps its own numbers as the floors. It leaves open a compromise of the code that holds that value, the kernel or the TPM service, and a change of PCR 7. [Design](src/md/features/rollback_floors.md)
- **The TPM floors kept across a change of PCR 7.** The policy of a floor names a key of the publisher (`TPM2_PolicyAuthorize`) in place of the value of PCR 7, so an update of `dbx` or of the firmware no longer lets one older signed system start and make its numbers the floors. [Design](src/md/features/rollback_floors.md)
- **Module records protected from their program.** The kernel marks each module record with its writer, and a program cannot change a record that its starter wrote. A report then says which modules a program really holds.
- **The network libraries become modules.** TCP, QUIC and the cryptography are loaded one time and imported, as the drawing module is. One correction then reaches every program that uses the network. [Design](src/md/api/library_modules.md)
- **Fresh bytes for a running program.** A program that runs a long time mixes new bytes of the entropy device into its own generator, now and then and never for each draw. A key that it makes late in its life then has bytes newer than its start. [Design](src/md/features/entropy_device.md)
- **A budget for each source of a QUIC flood.** A flood of new connections from one range of addresses spends only the budget of that range. Clients from other addresses then still connect while it lasts.
- **A log limit and a log time that the other programs do not set.** The log limit of each second is also counted in each budget above a program, and a `Log` waits for the serial port under the one log lock. A reader of its own records then no longer learns, from a refused record or from the time of a `Log`, how much the other programs wrote. [Design](src/md/features/own_log_ring.md)
- **A starter reads the log records of its children.** A program that starts programs receives their records from the log service, as it receives its own, and no record of another program. A test or a supervisor then shows what its children wrote without the right to read the whole machine. [Design](src/md/features/log_reader_scope.md)
- **Glyphs drawn on demand.** A font service draws the glyphs that a text needs into a shared cache, in place of a cache filled whole at build time. A principal then uses more fonts and more characters with no larger boot image.
- **The pushes and the indirect tail calls in the measure of the kernel stack.** The measure also counts a push of an argument outside a frame and a jump through a register to another procedure. The margin of the check then holds only for the bound of the graph. [Design](src/md/infrastructure/kernel_stack_depth.md)
