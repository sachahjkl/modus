A program can now run another system on the processor, in a guest, with the virtualization support of AMD processors.

A guest is a program that no thread runs: the memory that its holder maps in it is the memory of the guest. The holder runs the guest processor with one new kernel operation, `Guest_Run`. Each time the guest does what it may not do alone, such as a write to a port, the operation ends, and its result says what the guest did. The holder answers, then runs the guest again.

The program `guest_demo` shows it. Its guest is seven bytes of 16-bit code: it writes 42 to the port 0x80, then halts. The log says "guest_demo: the guest wrote 42 to the port 0x80, then halted after it". The kernel has 34 operations now.

Linux in a guest is the work that comes after this one.
