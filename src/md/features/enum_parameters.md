# Enum parameters

An export takes a value of a closed set as an enum. Its module file names the members, and that one description feeds each front end: the completion of the console, the check of a line before its call, and the row of buttons of the palette.

## The problem

- `settings.set(name: string, value: string)` took text for two closed sets. The console could not offer the values, found a wrong one only after the call, and the value of the second argument depended on the first, which no completion knew.
- Three processes each held a copy of the list of the settings: the console (`settings.descriptions`, to write the palette entries), the palette table (`Entry_Kind.Setting`, with the fields `setting` and `setting_value`) and the compositor (`settings_in_use`, to mark the value in use). A new setting, the scale, made the compositor write past an array of 6, and the console and the compositor counted the value in two units.
- The rule of the project says that a closed set is an enum, and that a word becomes its enum at the border. An export that takes text for a closed set breaks that rule at the border itself.

## The constraints

- Each front end reads the same description: no front end keeps its own list of a module.
- A wrong value is refused before the call, at its place in the line.
- No process gets a new right: the palette still dispatches through the console, its provider ([palette.md](palette.md)).
- The cost is paid once, at connect: completion filters a short list at each key.

## The chosen form

- **Enum is a type of the module format.** `module.Type.Enum` is a parameter or a result. The tables `Enums` and `Members` describe each enum: the name of its type, its size and sign, and each member with its name and its value. The format version is 6. A field of a record is never an Enum: a status field keeps its contract enum ([console_value_colors.md](console_value_colors.md)).
- **The describe step reads any enum of the module or of an imported package.** The type of a parameter or of a result that is an enum with a backing type of 1, 2, 4 or 8 bytes becomes an Enum. Each value is an integer literal or the value before plus one; the tool evaluates no other expression. A member is named in lower case: `French` becomes `french`.
- **The call carries the value of the member in a register.** The callee reads the low bytes of the size of the enum, as its compiler passes an enum of that size; a getter writes only those bytes, and each reader takes its result through `module.enum_value_of_register`. The receiver of an isolated call puts the whole register in the completion, as for an Integer (`isolated.completion_value`): a receiver that kept only Integer, Text and Table results gave 0, the first member, for each Enum result.
- **One named argument for each setting.** `settings.set` takes one optional argument for each setting, of the enum of its setting: `settings.set(keyboard_layout = .french)`. Each value is its own parameter, so no value depends on another, and the completion needs no special case. A call may give several settings at once.
- **An optional parameter crosses as a pair: a Presence word, then its value.** `Function.parameter_needs` has one byte for each parameter, `Required` or `Optional` (`module.Parameter_Need`). A call that leaves an optional parameter out gives the words 0 and 0; a call that gives it gives 1 and the value of the member. The callee reads the pair with `module.optional_member_of_arguments`, which refuses a Presence word other than 0 and 1, and a value that names no member. Each member keeps each value of its type: no value is taken for absence. The source states it with a parameter `<name>_presence: module.Presence` just before the parameter (`docs/MODULE_CONTRACT.md`, "Optional parameters and the settings of a parameter"). Refused: an absent word inside the range of the enum, each bit of its size set, which took one value from each enum and fit an Enum only.
- **The value in use comes from a getter that the parameter names.** The detail of an Enum parameter holds the index of its enum and the index of its getter export (`module.enum_detail_of`). The source names it with the attribute `enum_getters = "font = font, ..."`: the pairing is explicit, never found by a name. A getter takes no parameter, gives no error record, and gives an equal enum (`module.function_enums_check`). `settings.font()` and the six others are the getters of `settings.set`.
- **The console completes, checks and writes the member.** A line names a member after a dot, `.french`: Lex has a node `Member`, typed by the Enum parameter that receives it, as a record literal is typed by its Record parameter. The evaluator checks the name against the enum of its parameter at its place, before any argument of the call runs (`Member_Unknown`, `Member_No_Type`). The value of a call is an Enum value, drawn as `.french`; a value of another enum is refused as each argument of another type is. After a `.` at an argument of an Enum parameter, and with Tab at the start of such an argument, the completion lists the members.
- **The palette shows one row of buttons for each Enum parameter of an export whose call with one member is a choice:** an export of one parameter, an Enum, or an export whose parameters are each an optional Enum. Each member is an entry of the kind `Provider_Setting`, whose line is the call with that member; the entries of one parameter share the name of the row (the parameter) and the act name (`settings.set:font`), so the panel joins them into one row. Such an export has no entry of its own beside its rows. An export with other parameters opens as a form, whose Enum field takes its members as closed candidates (`Candidate_Kind.Member`), or in the console.
- **The getters are called when the panel opens.** At `Refresh` the console asks for a refresh of the marks and calls the getter of each row, and keeps each member in use by its act name. The table written after a line keeps those marks. After a line that the palette ran, the console asks for a refresh again, so the row shows the member that the choice set. A row with no getter, or whose getter gave no answer, has no mark: a getter that gave none removes the mark that its row kept.
- **The time zone is no argument of `set`.** A zone is a number of minutes, not a member of a closed set: `settings.set_time_zone("+08:00")` sets it and `settings.time_zone()` gives its text.
- **What went:** `Entry_Kind.Setting` and its fields `setting` and `setting_value` (reserved bytes now, version 7 of the palette table), `Candidate_Kind.Setting`, the built-in command `setting(name, value)`, `settings.get`, the copy of `settings.descriptions` in the console, and `settings_in_use` in the compositor. `settings.descriptions` stays for the window of `settings` only.

## The display text of a member

A member has two things, kept apart: its **name**, which is code, and its **display text**, which is for the principal.

- **The name** is what a line types and what a module compiles: `.fourteen_eighths`. It never changes with the language of the principal, so a line, a declaration and a test mean the same thing on every machine.
- **The display text** is what the palette and the completion show: "1.75". A module gives it for a member whose name is not the word that a principal reads; a member with no display text shows its name (`spleen`, `french`).
- **The texts are a table of the module file, apart from the enum.** Each row is a member and a language tag of BCP 47 (`en`, `fr-CA`), and holds one text. A module of the system gives the texts of one language, `en`, today. A translation is then one more set of rows for another tag, which a module or a later text module gives, with no change of the code, of the names or of the format. The reader follows the tags of the principal, each one shortened as the Lookup of RFC 4647 does, then `en`, else the name.
- **The completion shows both.** It lists `.fourteen_eighths   1.75`, and inserts the name: what a line holds is never a display text.

The built form:

- **The table `Member_Texts`** (table 18, format version 7) holds one `module.Member_Text` of 24 bytes for each row: the index of the enum in `Enums`, the number of the member in that enum from 0, and the text and the language tag in the string table. The rows are in the order of the enum, then the member, then the bytes of the tag (`module.member_text_order`), so two rows for one member and one tag are two equal keys, and a reader finds a row by a binary search. The file has the table when a module gives a text.
- **The language is a language tag of BCP 47 (RFC 5646), not an enum.** The languages are an open set: thousands of languages, with their regions and their scripts (`fr-CA`, `zh-Hant-TW`, `sr-Latn`). The rule "a closed set is an enum" does not hold for them, and the world names them with this standard, with its chains of fallback (`fr-CA`, `fr`, `en`). The pure package `modus:contract/language_tag` keeps the rules:
  - **Well-formed** (RFC 5646, section 2.1): a language of 2 or 3 letters with up to three extended languages, or of 4 to 8 letters; then a script, a region, variants, extensions and a private use, each of its form and in that order; or a private use alone (`x-private`). At most 35 bytes (`language_tag.TAG_CAPACITY`) and subtags of 1 to 8 characters. No registry is read: a well-formed tag of no known language is taken, as RFC 5646 lets a reader do.
  - **Refused: the grandfathered tags** (`i-klingon`, `en-GB-oed`): each has a preferred tag of the common form, and their list would be a special case of each reader.
  - **Stored in the canonical case** (section 2.1.1): `fr-CA`, `zh-Hant-TW`, `en-x-private`. The build writes each tag of a source in that case, and the check refuses another case, so two equal tags are equal bytes, and the order and the search compare bytes. A reader compares a tag that it is given with no regard to case.
  - **The Lookup** (RFC 4647, section 3.4): `language_tag.lookup_shorter` removes the last subtag, and a singleton that is then last (`zh-Hant-TW`, `zh-Hant`, `zh`).
  - **Refused: `module.Language`, an enum of the languages.** A closed set that is not closed: each new language would change the contract, and a region or a script would be a member of its own.
- **A display text** is 1 to `module.MEMBER_TEXT_CAPACITY` (24) bytes: the bytes of one button of a row of the palette. 24 bytes hold "1.375" and the longest word of a translation of the settings. Its characters follow one rule, `text_encoding.display_text_valid`, which the row of the file, the writer, the describe step and the check of the palette table each apply: UTF-8 with no control character, no character that a reader does not see or that changes the order of the text (`text_encoding.character_hidden`: U+200B to U+200F, U+202A to U+202E, U+2066 to U+2069, U+2028, U+2029, U+FEFF, the rule of the clipboard too), and one character at least that is not a space. A text of hidden characters or of spaces only is a button that a principal cannot read, and a mark of direction shows "52.1" for "1.25".
  - **Kept: a letter of another script that looks like a Latin one** (the Cyrillic Р in "РGB"). A translation needs each script, and a module that gives a misleading text can name its member with it too: the name, which a line types, stays ASCII and lower case.
- **The check**, `module.member_texts_check`, refuses a row that names no enum (`No_Enum`) or no member of its enum (`No_Member`), a text that is empty, past its bound, outside the string table or no display text (`Bad_Text`), a tag that is outside the string table, not well-formed or not in its canonical case (`Bad_Tag`), and a row that is not after the row before it (`Twice` for an equal key, `Out_Of_Order` for a smaller one). The writer of module files refuses the same parts with `Member_Text_Not_Valid`, and the check of the manual gives the problem kind `Member_Text`. The check of a replacement does not compare the texts: a text is not a part of the contract of a call.
- **The source: a declared table, apart from the enum.** A module declares an enumerated array of texts with the attribute `member_texts`, whose value is the language tag of its texts:

  ```odin
  @(rodata, member_texts = "en")
  scale_texts := #partial [scale_factor.Scale]string {
  	.Ten_Eighths = "1.25",
  	.Eleven_Eighths = "1.375",
  }
  ```

  The compiler checks each member and the type, so a renamed member breaks the build of the table and not a reader at run time. The describe step reads the table from the syntax tree: the enum must be the type of an Enum parameter or result of an export of the module, each text a string literal with no escape, and the tag well-formed (`language_tag.problem`); the build stores the tag in its canonical case, and refuses two tables of one enum and one tag, in any case. A table for another language is one more declaration with another tag. The variable is data in the read-only segment; no code reads it.
- **The settings** give texts for the scale (`1.25` to `2`), the subpixel order (`RGB`, `BGR`), the pointer theme (`owner`, `system`) and the keyboard layout (`US`): the members whose name is not the word that a principal reads.
- **The readers.** `module.member_display_text` takes the tags of the principal in the order of the preference, and gives the text of the first one that has a row, each tag shortened as the Lookup does before the next tag (`fr-CA`, `fr`, then `de`), then of `en` (`module.FALLBACK_TAG`), else the name of the member. A tag that is not well-formed is passed over whole: its pieces are no shorter tags of it. Until the interface in the language of the principal exists, the tags of the principal are the fallback `["en"]` (`principal_language_tags_fallback` of the console). `module.member_text_of_tag` is the search of one exact tag, with no fallback.
  - **The palette**: the button of a member and the name of its entry, "settings.set scale to 1.75", say the display text; the line of the entry, `settings.set(scale = .fourteen_eighths)`, says the name. The console makes no entry that does not fit the fields of the table, so the build refuses a module whose row would miss a button: the act name, the name of the row, the name of an entry, its line and its button each fit their bound, with the module as the service before the export (`palette_rows_fit` of the describe step). The compositor takes a value name and the name of a `Provider_Setting` entry as a text of UTF-8 with no control character, no more as ASCII only, so a translated text passes.
  - **The completion** lists the name, with the display text at the right of its row, and inserts the name. A member with no display text has the name of its enum at the right: "member of Font".
  - **The candidates of a form field** stay the names: the field holds what a line types.
- **No line types a display text.** The evaluator of Lex and the call of the tool read a member by its name only; "1.75" is a number, and `.1_75` is no name of a member.

Refused:
- **A member named by its display text** (`.1_75`, `.scale_1_75`). The name then carries a text for the principal, and a translation would change the code.
- **The display text in the enum, beside the member in the source of Odin.** The text then lives in the code, and a translation edits each module.
- **A display text that a line can type.** Two names for one member, and a line that means another thing in another language.
- **The texts in an attribute of the setter or of the getter** (`member_texts = "scale.ten_eighths = 1.25, ..."`). The compiler checks no member of a text in a string, and the texts of an enum that two exports share would be given twice.
- **The texts as fields of `Member`.** One language only, and a translation would change the record of each member, so the format.
- **A row for each member, with an empty text for no text.** Most members need no text; an absent row says it with no byte.

## The refused forms

- **Text for a closed set.** The console cannot offer the values and finds a wrong one after the call; the export parses a word that the border already knew.
- **One export `set(name, value)` with a completer for the second argument that reads the first.** It makes the completion of one export a special case, and every other export with a dependent argument needs its own.
- **A table of the settings in the console or in the palette.** It is a second copy of the contract of `settings`, which drifts: the crash of the compositor came from such a copy.
- **A getter found by its name.** A palette that looks for an export with the name of the parameter guesses: a rename breaks it in silence. The pairing is written in the module file.
- **Completion from the line history.** It guesses values; the type knows them.
- **A row of the palette for each enum parameter of each export.** An export with a required parameter beside its enum is a call with arguments, not a choice: it opens as a form or in the console.
- **The Enum as an Integer with a mark in its detail.** Each reader that does not know enums would then read a member as a plain number and call with any value. A new type makes the compiler name each switch that must take it.
- **A sentinel member, `Unchanged`, for a setting left out.** The console would complete it and the palette would show it as a button: it is no value of the setting.
- **A getter called after each line.** It is one call for each row after each line; the design calls each getter when the panel opens, where the mark is read.
- **The rows of `settings` with no connection.** The palette lists what the console can call now ([palette.md](palette.md), "The scheduling strategy"): the rows appear after `connect("settings")`, as each export of a service does.
- **A default value of the source as the mark of an optional parameter.** A default of a parameter of a procedure "c" is a fact of the Odin callers only, and no reader of the call sees it.

## The subtle points

- **A member is named, never numbered.** A line names `.french`; the console writes the value of the member that the module file gives. A value that names no member is refused at the border of the export too: `settings.choice_of_arguments` takes each argument through `enum_word.member_of_argument`.
- **The value of a member is part of the contract.** An enum that crosses the border gives its values explicitly, so a new member never moves the value of another. Two enums are one when their names, sizes, signs, member names and values are equal (`module.enums_equal`): the check of a replacement compares them so, and the need of each parameter too; the getter is an index of one file and is not compared.
- **Absence is a word of its own, not a member.** The Presence word before the value says it, so no value of an enum is reserved for absence, and the check of a replacement compares the need of each parameter (`module.function_needs_check`).
- **A member that each window does not pay.** `scale_factor.Scale` names the scales from 1 to 2, and the export takes each: a window whose budget cannot pay a scale declines it, which is a fact of the window and of the compositor, not a refusal of the export.
- **The count of entries.** One entry for each member of each row is a few tens of entries for the settings: 29 for the seven settings, within the 256 of the table. The palette with any count of entries ([palette.md](palette.md), "Any count of entries") removes the bound of the table.
- **A getter is a call of a service or of an isolated process, on the thread of the lines.** The first thread holds the keys and never waits for another process: at `Refresh` it sets one word and wakes the thread of the lines, which owns the rings of the services. That thread calls the getters when no line waits. A line entered while a refresh runs waits for its end before it starts: at most `PALETTE_GETTERS_LIMIT`. The panel opens at once on the table of now, and the marks arrive when the getters answer.
  - **After a choice of the palette** the getters run once the line ended, so the keys are free, and before the save of the line history, so the new mark does not wait for a commit of the storage service.
  - **Two facts make the marks testable with no wait for a time.** "console: the palette marks .spleen for settings.set font" follows the write of a table whose mark moved; "console: the palette refreshed its marks: …" ends each refresh, with the count of getters sent and of getters in the process of the console not called. A picture of a mark waits for the first; the test of a loaded module waits for the second, and fails on the fact of its getter (`hostile_exports.mode`).
  - **One bound for the whole refresh**, 1 s (`PALETTE_GETTERS_LIMIT`): N rows of a slow service hold the thread of the lines for at most that time, not for N times it. A service that missed a getter (no answer, a refused call, or a stop) is asked nothing more in that refresh.
  - **No getter of a module in the process of the console.** A direct call has no bound: a getter that loops would hold the console for good. A module that `load` placed in the console has rows with no mark; `isolate` gives its getters a bound.
  - **Refused: the getters on the first thread.** A slow service held the keys for 1 s for each row, and a direct getter that loops froze them for good.
  - **Refused: to clear the marks at each open.** The marks of the last refresh stay until the getters answer, so a mark does not blink at each open; a getter that gives no member removes its mark.
- **A name in a line of the palette is a name of Lex.** The line of a row is built from the name of the export, of its service and of its parameter, which another party wrote in its module file: `h.f(a = .x)`. The console makes no command of an export whose name or a name of a parameter is no name of Lex (`lex_parser.name_valid`), so a parameter named `a=shutdown(),b` cannot put a call of its own in that line. A member name is checked by `module.enum_type`.
- **The flag of the compiler.** `log_fact`, `enum_getters`, `member_texts`, `parameter_ranges`, `parameter_choices` and `parameter_instances` are custom attributes that the compiler ignores with one flag (`foundation.CUSTOM_ATTRIBUTES_FLAG`); the tool reads them from the syntax tree.

## State

Built: the type Enum and the tables of the format, their checks (`module.enum_type`, `module.function_enums_check`, the manual's check of a file, the writer of module files, the check of a replacement), the describe step with the two attributes, the border `enum_word.member_of_argument`, the console (the member of Lex, its check, the optional parameters, the completion, the drawer), the call of the tool (`modustool call` with named arguments and members), the palette rows with their getters, and `settings.set` with its seven getters, `set_time_zone` and `time_zone`. The display text of a member: the table `Member_Texts` with its language tags (format version 7), the package `language_tag` (well-formed, canonical case, Lookup), the check of the texts in the format, the writer and the manual, the declared tables of the source and their attribute `member_texts`, the texts of the settings, the palette rows and the completion that show them, and the rule of the compositor that takes a display text in a value name.

Left:

- An import declaration of an export with an Enum parameter: the tool reads no enum in a `foreign` declaration yet, so an importer cannot declare one.
- A record field of an enum of a module stays a plain Integer: the field kind Status names contract enums only.
- The manual shows an Enum parameter by the name of its enum; a page that lists its members waits for a need.
- The language of the principal: each reader passes the fallback `["en"]`. The interface in the language of the principal gives the tags of the principal in its place, and the rows of the texts of each tag.
- The candidates of an Enum field of a form of the palette are the names, with no display text: a candidate holds a name only.
