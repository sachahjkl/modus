# The reuse list: what the system takes from others, checked

## Purpose

The reuse list is the section "Reuse list" of [`docs/PROPERTIES.md`](../../../docs/PROPERTIES.md). It names each reused work: a work that others wrote, and that the system ships in a module or in the boot image, or that the repository holds as a copy. For each one it gives the place, the license as an SPDX identifier, and the file that holds the text or the notice of that license. A reader who wants to know what of others is inside the system reads one table, and the table is true because `modustool check` compares it with the repository.

The rules of the check, as a guide: [`docs/TOOLS.md`](../../../docs/TOOLS.md), "The reuse list".

## Constraints

- The list names what the system ships or copies. A tool of the host that builds or tests the system is not a part of it: the compiler, LLVM, nasm, QEMU, OVMF, swtpm, OpenSSL, the flake inputs. The page of the licenses of the site lists those ([`docs/SITE.md`](../../../docs/SITE.md), "The licenses").
- A design, a standard or a specification is not a reused work. io_uring, Nix, bcachefs, UEFI, the TPM, WebGPU, the BLAKE3 specification and the RFCs are in the field **Reuse** of each property, or in the guide of the part. No code of them is in the system.
- A candidate is not a reused work. A library that the system could use one day is a line of the property that names it, not a row of the list.
- The license is read at the source of the work, and the repository records what was read: the `.license` file of a font, the head of a pointer manifest, the credits of the portraits, the head of a license file of a copied source. The check compares the list with that record, not with memory.
- The license is an SPDX identifier, or an SPDX expression of identifiers with `OR` and `AND`. `NONE` is the SPDX value of a work with no license: a credited frame of a video, all rights reserved.
- Each row names a file of the repository with the text of the license, or the notice that the license asks for. A license of Creative Commons accepts its address in place of its text; for it the file is the notice with the attribution and that address.

## The chosen form

- **A table of four columns in `docs/PROPERTIES.md`**: the work, its place, its license, its license file. The place and the license file are paths of the repository in a code span. The table stays in the document of the properties, because the rule "Reuse proven software where it fits" of its objective is the reason the list exists.
- **The place is the key.** The check matches a row and a reused work by the place alone. A path is exact; a name of a work is free text that a writer can change.
- **The tool derives the reused works from the records that the build and the site already read**: the three lists of fonts of `vector_fonts.odin` with their `.license` files, the font data of Spleen and its `FONT_LICENSE`, the manifest of each pointer theme whose license is not the license of the repository, `origin.manifest` of the cryptography with the two license files beside it, the credits file of the portraits, and the imports of the sources of the system. The list is checked against the same facts that the site shows.
- **The libraries of the compiler are reused works.** The compiler compiles `base:runtime` into every module and into the boot program, with no import. A package of `core:` that a source of the system imports, and that is not a test, is compiled into its module: `core:reflect` in the module `cryptography`. Their place is the import path, and their license file is `LICENSE.odin.txt`, the license of Odin that the repository already holds.
- **Four faults.** A reused work with no row. A row whose place is no reused work: the repository does not hold or use it. A row whose license is not the license that the record gives. A row whose license file does not exist, or is not the file that the record names.
- **A pure procedure and its host test.** The procedure takes the text of the document, the reused works and a test of existence of a file, and gives the problems. A host test gives it a good list and a bad list. The reader of the repository is a second procedure.

## Refused forms

- **A separate file `LICENSES.md`, or the README, as the list.** The page of the licenses of the site proposes `LICENSES.md` for its prose facts; a second table of the same works would disagree with this one. The README section "Licences" is prose for a reader and links to the list.
- **The list generated by the tool.** A generated list says what the code holds, and no reader checks it. A list that its writer keeps and that the tool compares says what was decided, and the tool proves that it is true.
- **The match by the name of a work.** "Paper Mono" and "Paper Mono ASCII" are the same work. The path has one form.
- **One row for "the fonts".** Each font has its own author and its own record. A row for a group hides a font with another license.
- **The licenses of the tools of the host in the list.** They do not reach a machine that runs the system. A reader of the list asks what is inside the system.
- **A license from memory.** The former list said "Licences in this table come from memory". A license is now a fact of a record of the repository, or the check refuses the row.
- **A check that downloads the source to read its license.** The check runs in the sandbox of the flake, with no network. The record of what was read is the evidence; a change of the source is a new record, in the commit that takes the new source.

## Subtle points

- A test file is not shipped. A file whose name holds `_test`, or whose first line is `#+build !freestanding`, is not read for imports: test vectors from an RFC are facts in a test, not a reused work.
- The theme of the system (`resources/pointers/system.manifest`), the font of the name of the mark and the pictures of the mark are works of the system, under the license of the repository. They are not rows.
- The Posy theme is not in the repository and not in a published image ([release_image.md](release_image.md)). The boot image of a development build holds it when the build has its input, so the system ships it to a developer, and it is a row. Its place is its manifest, which is also its notice.
- The portraits are rows one by one: the credits file can hold a picture under one license and a picture with none.
- `site_spdx_names` of the site translates the words of a record into an identifier. A record whose words have no translation gives no identifier, and the check then compares nothing for that row: add the translation, or write the identifier in the record.
- The fiat-crypto field arithmetic is a row of its own, because Odin took it under another license (BSD-1-Clause) than the rest of `core:crypto` (Zlib).
